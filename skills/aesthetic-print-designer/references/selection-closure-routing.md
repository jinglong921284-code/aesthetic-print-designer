# Selected-Print Closure Routing

Use this reference after a creative direction is selected and the user requests tracked closure, sampling preparation, specification work, or handoff. Selection approves the direction; it does not automatically authorize local persistence or an external action.

## Permission preflight

Resolve these separately:

1. **Creative approval:** exact selected direction and approval wording.
2. **Local scope:** approved project directory, Print ID, design name, exact source bytes, and whether closure files may be created there.
3. **Architecture:** repeat, placement, border, engineered, or panel.
4. **External scope:** each cloud document, upload, email, supplier contact, or transfer target and the specific authorized action.

If an external target or action is missing, prepare the local package and stop with that gate pending. Never treat a selected design, an existing URL, or access to a connector as authorization to write or send.

## Architecture routing

### Repeat architectures

Use the machine-tracked state in `references/selection-closure-state-machine.md` when the local persistence scope is approved. The default document mode is `local`; it validates the local source, mockup, role-locked colour specification, repeat evidence, checksums, and final audit without requiring Feishu.

Use Feishu mode only when the user selected the exact Feishu document and authorized the update. A successful write is not proof: refetch the full Print-ID section as the user and run the row/cell consistency audit.

### Placement, border, engineered, and panel architectures

Do not run repeat repair merely because a design was selected. Record, as applicable:

- artwork boundary and physical scale;
- orientation, anchor, garment zone, or named pattern piece;
- border depth and corner behavior;
- seam crossings, mirrored pieces, bleed, registration, and tolerance;
- clean artwork, approved mockup, role-locked colour specification, file metadata, and checksums.

Report the architecture-specific evidence as `complete`, `revise`, or `pending`; do not label it `digital seamless repeat passed` unless it is actually a validated repeat.

## Local completion versus delivery

A local closure can finish with a versioned package, checksum manifest, specification draft, visual evidence, and pending external gates. Uploading, sending, contacting, or recording a supplier receipt is a separate action. Never claim a delivery or receipt without evidence from the authorized channel.
